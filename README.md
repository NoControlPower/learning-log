# learning-log

**每周一个工程问题。不是笔记，是"我搞清楚了什么、怎么证明的"。**

> 这个仓库的目的只有一个：把"我看过/我做过"变成"我能复述、能验证、能复用"。
> 它也是我的技术档案：一年后回看，应该能看出判断力在变强。

## 写作规范（每条必须满足）

1. **一个具体问题**，不是知识面；
2. **有证据**：代码路径 / 波形 / 日志 / 数据，至少一个；
3. **有结论**，且说清适用范围和反例；
4. **有可复用点**：下次遇到同类问题怎么快速判断；
5. 不抄教程、不写"XX 简介"、不贴公司机密。

## 为什么公开写（不是做自媒体）

参考 swyx 的 [Learn In Public](https://www.swyx.io/learn-in-public)：

- 写作对象是**三个月前的自己**，不是读者；点赞数不作为指标；
- 公开犯错会被更快纠正，这比"显得专业"更值钱；
- 长期积累的"学习弃物"会变成别人搜到的资料，也会变成你面试时讲得出来的细节。

所以：短、真、有证据 > 长、全、像教程。

## 主题偏好（2026-11 更新）

1. **中文优先**：英文源只作线索，输出一律中文；
2. **每周固定含 1–2 条"别人怎么用 AI"**：谁、做了什么、效果数字、我能不能用；
3. 工程问题（RTOS/低功耗/协议）与 AI 用法并重，不要只写纯技术。
